# Интерфейсный этап 4: главная, кабинет, проект и проверка

Основа — опубликованный `c6a621a`. Ветка — `codex/interface-workspaces`.
Продолжает общую систему элементов, одобренный фон и обе темы. Новых продуктовых
функций, схемы БД, зависимостей и внешних подключений нет.

## Что доработано

| Найденное затруднение | Изменение |
| --- | --- |
| Следующее действие объясняется в закрытом раскрытии | Инструкция видна на главной и над задачами/результатом этапа |
| На телефоне замечания и проверка скрываются за задачами | Проверяемый, возвращённый и принятый результат открывается первым; явная ссылка на задачу сохраняет приоритет |
| На узком экране у этапов скрыты подписи состояния | Пять этапов показаны вертикально, с названием и реальным состоянием |
| На главной после пяти принятых этапов остаётся номер «05» следующего шага | Маркер меняется на защиту или завершение; этапы, защита и оценка независимы |
| Одинаковые названия трёх рабочих этапов | Краткие подписи «Работа · 1/2/3», полные названия внутри этапов сохранены |
| Очередь показывает пустое «Материал и команда» | Пустое раскрытие убрано, команда и информационный отчёт названы по содержимому |
| Текущая сдача визуально смешивается с прежним замечанием | Предыдущее замечание отделено раскрытием; у пересдачи есть переход к истории |
| Неочевидны основное решение и условие возврата | Первая актуальная работа выделена; рядом с комментарием указано условие возврата |
| Нового учителя встречают пустые счётчики | Показан первый шаг подключения; пустые сроки и фильтры скрыты |
| Возврат из проекта к проверке требует искать меню | У учителя есть прямая ссылка к очереди проверки |
| На телефоне фильтры задач имеют шрифт 12–13 px, кнопки редактора разной ширины | Ввод — 16 px, действия редактора и решения выровнены по ширине |
| Создание проекта меняет содержимое, оставляя заголовок и адрес главной | Адрес, заголовок, контекст и фокус поля названия синхронизированы; Back и модифицированные ссылки сохранены |
| Подтверждение сохранения черновика остаётся за открытым редактором | Настоящее сообщение сервера переносится внутрь модального редактора и сохраняет роль `status`/`alert` |

В обзоре проекта основной шаг, руководитель и принятые этапы отделены от сводки
задач. Повторяющиеся счётчики и действия сокращены; полный маршрут и задача со
сроком остаются доступны в раскрытиях. У задачи и этапа сохраняется собственное
состояние. Процент задач не принимает этап и не публикует оценку.

## Границы

- Пять этапов, критерии и шкалы, история, защита, личные оценки, команды,
  группы, приглашения и согласование руководителя сохранены.
- Серверные обработчики, права, ревизии конкурентных изменений и POST/CSRF
  не заменены клиентской логикой. Поведение без JavaScript сохранено.
- Старые URL, ссылки на этапы/результаты/задачи и переходы из уведомлений работают.
- `work-screens.css` загружается только на главной, в кабинете и пространстве
  проекта. Вход и профиль из предыдущего этапа не переоформляются.
- Остальные страницы, хранение материалов, новая аналитика, общая архитектура
  и эксплуатационные задачи не входят в этот выпуск.

## Стенд

```powershell
python tests/preview_workspaces.py
```

`http://127.0.0.1:5116/__workspace/student/home`

Роли: `student`, `teacher`, `new`, `empty-teacher`.
Экраны: `home`, `review`, `project`, `work`, `submitted`, `returned`, `finished`,
`draft`, `resubmitted`, `accepted-stages`, `long`.
Например: `/__workspace/teacher/resubmitted`.

Стенд привязан к loopback, создаёт временную SQLite-базу и использует фиктивную
почту. Он не открывает рабочую базу и не отправляет реальные письма. Маршруты
стенда не регистрируются в обычном приложении `app:app`. Данные сбрасываются
при перезапуске; завершение — Ctrl+C. Не публиковать этот стенд в сети.

## Проверено локально

- 741 Python-проверка; PostgreSQL проверяется отдельно в CI. Локально 305 пропусков.
- Все 12 наборов JavaScript. Новые регрессии проверяют выбор результата,
  приоритет явной ссылки на задачи, создание проекта/фокус/Back и сообщение
  сервера внутри редактора.
- 128 сочетаний основных экранов и состояний, четырёх вариантов пользователей,
  светлой/тёмной тем и ширин 320/390/900/1440 px. Один заголовок страницы,
  отсутствие горизонтального переполнения, видимость активного результата и
  размер ввода на телефоне не меньше 16 px.
- Ещё 8 сочетаний темы и ширины: переход к созданию проекта, заголовок,
  контекст навигации, фокус поля названия и возврат Back.
- В браузере на синтетической базе: создание первого проекта, черновик без
  руководителя и запрет отправки, ошибка пустого результата, ошибка возврата без
  комментария, возврат, исправленная сдача, принятие и открытие следующего этапа.
  В истории проверены обе отправки и соответствующее решение.
- Новые общие SQLite/PostgreSQL-регрессии проверяют реальные переходы состояний,
  отделение прежнего замечания, пустое поле нового решения и приватность очереди.
  Существующие проверки прав, CSRF, истории и оценок сохранены.

CI, Auto-Deploy точного коммита и публичные проверки выполняются отдельно после
локальной проверки. Рабочие данные и настройки Render/Neon не меняются.
Авторизованные рабочие аккаунты и настоящие письма не используются; эмуляция
ширины не заменяет физический телефон или экранный диктор. Проверки не означают
отсутствие всех возможных ошибок.
