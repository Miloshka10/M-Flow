# Интерфейсный этап 3: доступ и аккаунт

Основа — опубликованная система элементов `baf0738`. Сохранены спокойные
иллюстрации, обе темы, адреса страниц и существующие серверные обработчики.

## Решения

- Вход и регистрация: связанные группы «подпись — поле — подсказка — ошибка»,
  одинаковые размеры полей и кнопок. Код регистрации учителя расположен перед
  личными данными; код группы или проекта его не заменяет.
- Восстановление: один следующий шаг, нейтральный ответ на запрос письма,
  повторный запрос под раскрытием. Недоступная отправка не отмечается успехом.
- Ссылка из письма: код удаляется из адреса браузера и подставляется локально,
  подтверждение требует отдельного POST. Без кода поля нового пароля скрыты;
  ручной ввод и обычная POST-форма остаются доступными без JavaScript.
  Готовность формата кода не означает, что сервер признал ссылку действительной.
- Истёкшая/использованная ссылка: явный путь к новому запросу, без повторного
  вывода отклонённого кода или пароля. После сброса учитель возвращается к входу учителя.
- Профиль: данные аккаунта и готовность восстановления видны отдельно.
  Смена пароля раскрывается по запросу; при ошибке раздел открыт и получает фокус.
  Ссылки на навыки ученика и оформление сохранены.
- Почта: действующий адрес, ожидающий адрес и отдельные подтверждения каждого
  ящика. Одно подтверждение при смене адреса не обозначает завершение смены.
  Повторная отправка/изменение скрыты в раскрытии; ошибка открывает его.

Не менялись срок действия и одноразовость токенов, отзыв сеансов, ограничения
попыток, допуск учителя, права, CSRF, схема БД, провайдер и содержимое писем.

## Воспроизводимый стенд

```powershell
python tests/preview_access.py
```

Открыть `http://127.0.0.1:5114/__access/student/none/profile`.
Тестовые маршруты существуют только в этом процессе, привязанном к loopback.
Приложение `app:app` их не регистрирует. База временная, адреса вымышленные,
диспетчер почты подменён; настоящие письма не отправляются. Завершение — Ctrl+C.

`/__access/<role>/<state>/<screen>`:

- роль: `student`, `teacher`;
- состояние: `none`, `pending`, `verified`, `changing`, `old-ok`, `new-ok`,
  `long`, `unavailable`;
- экран: `profile`, `email`.

`/__access-public/reset-ready`, `confirm-ready`, `reset-success`, `confirmed`,
`pending-confirmation` — образцы интерфейса. Первые два проверяют только
подстановку кода правильного формата; образцы успешных ответов сами по себе
не доказывают смену пароля или подтверждение почты. Эти операции проверяют тесты.

## Проверки перед выпуском

- 736 Python-тестов: успешно; локально пропущены 303 проверки, включая
  PostgreSQL. CI выполняет полный прогон с PostgreSQL 18 на Python 3.12 и 3.14.
- Все 12 наборов JavaScript: успешно. Добавлены регрессии ручного ввода кода,
  готовности формы и восстановления страницы из истории.
- Браузер: 352 сочетания экранов/состояний, обе роли, две темы,
  ширины 320/390/900/1440 px. Проверены один заголовок страницы, отсутствие
  горизонтального переполнения и размер видимых полей не меньше 16 px.
  После последней правки разметки повторно проверены 32 сочетания входа/регистрации,
  активная роль и размещение кнопок показа пароля внутри полей.
- Вручную: ошибки входа обеих ролей, сохранение логина и очистка пароля,
  показ/скрытие, фокус, клавиатура и Escape меню, раскрытия профиля/почты,
  нейтральный ответ восстановления, удаление fragment-кода из адреса.
- На временных базах: реальное подтверждение, смена двух ящиков в обоих порядках,
  сброс обеих ролей, отзыв сеансов, повторное использование/истечение ссылки,
  отрицательные проверки прав и CSRF. Новые регрессии проверяют показ частичного
  подтверждения, приватность адреса профиля и отсутствие ложного успеха.

Рабочие данные и настройки Render/Neon не менялись. Реальные письма и вход
в рабочие аккаунты повторно не проверялись. Физический телефон и экранный диктор
не проверены. CI, публикация и публичная проверка фиксируются отдельно в выпуске.

Следующий интерфейсный этап — рабочие экраны; здесь он не начат.
