# Графика M-Flow — проектная мастерская

Направление согласовано пользователем после просмотра главной иллюстрации в контексте страницы.
Обновлены только изображения и их размещение в прежних областях. Структура страниц,
палитра, тексты, формы, роли, права доступа и данные не менялись.

## Аудит

Прежний `static/project-kit.svg` использовался в приветствии ученика, кабинете учителя,
входе/регистрации и пустом состоянии. Самостоятельного визуального смысла для
каждого контекста нет. Плавающие плюс, стрелка, галочки и повторяемая папка создают
ощущение увеличенной иконки, а не законченной иллюстрации.

Кольцевой индикатор задач, число ожидающих проверок и статусы полезны: они отражают
реальные данные. Их менять не предлагается. Обычные стрелки перехода тоже полезны;
отдельная крупная стрелка в «Сильнее вместе» — кандидат на предметный знак команды
или удаление обводки, а не повод добавлять ещё одну большую картинку.

## Источники и направления

Официальные главные страницы просмотрены 15 октября 2026:

- https://linear.app/ — продуктовый интерфейс сам служит графикой. Для M-Flow:
  точные фрагменты рабочего процесса вместо выдуманных диаграмм.
- https://www.notion.com/ — крупная типографика и предметная связь графики с
  демонстрацией продукта. Для M-Flow: один фокус, не нагромождение символов.
- https://practicum.yandex.ru/ — фотографии встроены в композицию вокруг текста.
  Для M-Flow: предметы, связанные с учебной работой, и ясное разделение текста/изображения.
- https://www.tbank.ru/ — открыть и проверить актуальную графику не удалось:
  веб-загрузка завершилась таймаутом, браузер сообщил ошибку сертификата.
  Предупреждение не обходилось; конкретные приёмы этого сайта не приписываются ему.

Варианты: (1) реальный интерфейс, (2) предметный исследовательский стол,
(3) редакционные технические схемы. Для первого образца выбран вариант 2:
бумажный макет моста стоит на чертежах, рядом жёлтый карандаш и зажим.
Это метафора «от идеи к результату», не реальный проект пользователя и не интерфейс.
Чужие изображения, логотипы и иллюстрации не копировались.

## Реализация и размеры

- Главная ученика: макет моста на чертежах — одобренный образец.
- Вход и регистрация обеих ролей: исследовательский блокнот с рисунком и образцом листа.
- Кабинет учителя: проектные материалы с лупой — просмотр и проверка, не сдача работы.
- Пустое состояние: лёгкий SVG чистого листа вместо повторения большой иллюстрации.
- Блок «Сильнее вместе»: небольшой SVG участников вместо большой обведённой стрелки.

Предметные изображения декоративные, не представляют реальные работы пользователя.
Важный текст остаётся HTML, счётчики и прогресс по-прежнему берутся из данных.

| WebP | 480×360 | 960×720 |
| --- | ---: | ---: |
| research-bridge | 46 598 байт | 141 760 байт |
| research-notebook | 34 392 байт | 112 346 байт |
| review-study | 31 806 байт | 98 744 байт |

Все шесть WebP вместе — 465 646 байт; страница использует только свою композицию,
браузер выбирает один размер через `srcset`. SVG — меньше 1 КБ каждый.
Исходные PNG с альфа-каналом и полные запросы (`PROMPT.md`,
`research-notebook-PROMPT.md`, `review-study-PROMPT.md`) сохранены здесь, вне `static`.
Все три изображения созданы встроенной генерацией; референсом двух новых служил
собственный согласованный мост. Векторные знаки написаны как простой SVG.

`build_asset.py` только масштабирует и кодирует WebP с сохранением прозрачности,
не меняя композицию и не обрезая изображение. Для повторной сборки нужен Pillow
в инструментальном Python; зависимость приложения не добавлялась:

`python design/graphics-v1/build_asset.py`

Результат записывается в `static/illustrations/`. Отдельный `graphics.py` формирует
одинаковую доступную разметку; `static/graphics.css` ограничен рисунками,
не добавляет анимации, цветов фона или перестройки сеток. Сохранено прежнее скрытие
декоративного рисунка учителя на узких экранах, чтобы оставить место работе.
Размеры 4:3 зарезервированы до загрузки; `alt=""` исключает декоративную графику
из чтения скринридером. У пустого состояния `loading="lazy"`. WebP MIME явно
зарегистрирован для одинаковой раздачи в Windows и Linux.

## Изолированный предпросмотр

Из корня: `.venv/Scripts/python.exe tests/preview_notifications.py --results --graphics`.
Адрес `http://127.0.0.1:5091/login`, аккаунты `preview-student`, `preview-teacher`,
`preview-empty`, тестовый пароль у всех — `preview-only-123`.
Это синтетические данные только во временной SQLite; рабочая Neon не используется.
Данные не подключаются к обычному запуску сайта. Ctrl+C завершает сервер.
Предварительный подменяющий HTML маршрут удалён: проверяются настоящие шаблоны.

## Проверки

`test_graphics.py` проверяет реальные заголовки WebP: размеры, прозрачность,
целостность длины и бюджет каждого файла; разметку, локальные пути, SVG без
исполняемого/внешнего содержимого и отсутствие новой анимации.
Тесты кабинета проверяют все страницы авторизации, обе роли, пустое состояние,
корректный MIME, доступность изображений, неизменность содержимого/данных при просмотре
и недоступность исходников по HTTP. Старый SVG удалён после проверки ссылок;
он доступен в истории Git.

Локально: 459 Python-тестов, 269 выполнены успешно, 190 PostgreSQL-проверок пропущены
без отдельного локального сервера. Четыре набора JavaScript-тестов пройдены.
PostgreSQL проверяется существующим GitHub Actions на временной базе, не рабочей Neon.
Скриншоты сохраняются вне публичной папки сайта; сравнение «до» — с исходным снимком
пользователя, «после» — с изолированным локальным приложением.

В браузере проверены главная ученика с проектами и пустое состояние, кабинет
учителя, все четыре страницы входа/регистрации. Для авторизации проверены 1280×900
и 390×844 в обеих темах: изображения загружаются, горизонтального переполнения нет.
Кабинеты проверены в обеих темах на компьютере и телефоне; промежуточные размеры
главной иллюстрации дополнительно проверялись при согласовании образца.
Проверены вход обеих ролей, выход, ошибка входа, несовпадение паролей регистрации,
переход из пустого состояния к форме проекта и клавиатурный фокус.

Физические телефоны и production после Auto-Deploy отдельно не проверялись.
Настройки Render/Neon не менялись; дополнительный production-деплой не запускался.
