# Этап 2 интерфейса: система элементов M-Flow

Основа: опубликованный `1924244`. Ветка: `codex/interface-components`.
Общие элементы внедрены и проверены локально; CI и публикация проверяются отдельно.
Это второй этап **интерфейсного** плана, а не этап резервного копирования общего плана.

## Что стало общим

`static/components.css` загружается перед композицией страниц `interface-v3.css`.
Палитра, типографика и базовые элементы перенесены из файла композиций;
цвета прежних модулей связаны с теми же семантическими переменными.
Оригинальные CSS отдельных разделов пока сохраняются: их постепенное сокращение
проводится вместе с переносом соответствующего экрана, без смены стека.

| Основа | Правило |
| --- | --- |
| Отступы | Шкала 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 px |
| Поля и основные кнопки | 48 px; комфортный режим доступа — 52 px; компактные действия — от 44 px |
| Текст | Подписи 13–14 px, основной текст 15 px, вспомогательный 12–13 px; ввод на телефоне 16 px |
| Скругления | Небольшие элементы 8 px, поля 9 px, карточки 16 px, крупные поверхности 20 px |
| Действия | Основное / второстепенное / текстовое / удаление; доступное, отключённое, ожидание ответа и фокус |
| Поля | Обычное, только чтение, отключённое и ошибка после проверки; подпись, подсказка, сообщение |
| Состояния | Нейтральное, проверка, доработка, принято; подпись всегда остаётся словами |
| Сообщения | Информация, предупреждение, успешное сохранение, ошибка; ожидание не выглядит как успех |
| Поверхности | Карточки, раскрывающиеся пояснения, меню и существующие панели задач/результатов |

Контур полей сделан заметнее на белой карточке. В светлой теме измеренное
отношение контраста контура активного поля к его фону — 3,07:1;
текста проверенных образцов кнопок/статусов/сообщений — не менее 4,63:1.
Это локальные измерения элементов, не заявление о соответствии всего сайта WCAG.

## Повторное использование

- `ui_components.state_badge()` использует реальную подпись из существующей логики
  и безопасно экранирует её. Главная, карточки проектов и личные результаты используют
  общую отрисовку; старые классы и селекторы сохранены.
- `ui_components.notice()` экранирует текст уведомления и сохраняет `status`/`alert`.
  Общая оболочка страниц команд, групп, руководства и завершения проекта использует его.
- Существующие `.error`, `.success`, `.auth-error`, поля, кнопки и карточки подключены
  к общим правилам без замены обработчиков. `data-ui-tone` задаёт оформление, не права
  и не состояние работы. Не выводить тон на основании количества выполненных задач.
- Для новых локальных фрагментов есть `.ui-field`, `.ui-field-hint`, `.ui-field-error`,
  `.ui-actions`, `.ui-surface`, `.ui-notice`. Подсказка находится вне `label` и связана
  с полем через `aria-describedby`; ошибки — через `aria-invalid` и описание.
- Анимация ожидания учитывает настройки движения; обычное отключение кнопки
  отличается от ожидания ответа формы с `aria-busy`.

## Исправления найденных проблем

1. Второстепенная отключённая кнопка больше не сохраняет активное оформление,
   включая наведение; ожидание отправки остаётся отдельным состоянием.
2. Граница ошибки поля больше не перекрывается обычной границей из каскада.
3. Кнопка закрытия мобильного меню имеет согласованную область не менее 44 px в обоих направлениях.
4. Ошибка результата этапа открывает вкладку результата и получает фокус, в том
   числе после старой ссылки на другой этап. У ученика сообщение находится внутри
   открытого редактора, у учителя — рядом с формой решения. Текст и серверное состояние
   сохраняются; последующая навигация не блокируется сообщением об ошибке.

## Воспроизводимый стенд

Из корня проекта с установленными зависимостями:

```powershell
python tests/preview_components.py
```

Открыть `http://127.0.0.1:5112/__components`.
Переходы для тестовых ролей: `/__review/student/profile`,
`/__review/teacher/profile`, `/__review/new/profile`.

Стенд использует существующие фикстуры тестов, новую временную SQLite-базу,
фиктивную почту и привязку только к loopback. Реальные письма не отправляются;
тестовые маршруты не регистрируются при обычном запуске `app:app`.
Данные примеров сбрасываются при перезапуске. Завершение — Ctrl+C.
Не запускать этот стенд на production и не менять адрес привязки на публичный.

`gallery.html` и `gallery.css` оформляют только каталог разработчика.
Каталог не добавляет пользователям новый раздел и использует реальные стили приложения.

## Проверено

- 728 Python-тестов: успешно, 299 PostgreSQL-проверок пропущены локально.
  Обязательный PostgreSQL-прогон выполняется в CI на Python 3.12/3.14.
- Все 12 наборов JavaScript. Новые регрессии проверяют выбор и фокус ошибочного
  результата, сохранность состояния и текста, экранирование общих элементов.
- 376 сочетаний страниц, четырёх видов входа (публично, ученик, учитель, новичок),
  тем и ширин 320/390/900/1440 px. Горизонтальное переполнение не найдено;
  видимые текстовые поля на узких экранах — 16 px.
- Реальные POST на синтетической базе: отчёт задачи, повторная сдача, ошибка
  возврата без комментария, возврат, ошибка пустой сдачи внутри редактора,
  исправленная сдача и принятие. Следующий этап открылся, история сохранена.
- Ошибки входа обеих ролей, показ/скрытие пароля, клавиатура и Escape меню/панелей,
  возврат фокуса, обе темы и длинные подписи.

Рабочие аккаунты, данные, настройки Render/Neon и схема БД не менялись. Физический телефон,
экранный диктор и реальная доставка писем в этом визуальном выпуске не проверялись.
Проверки не гарантируют отсутствие всех возможных ошибок.

## После этого этапа

Система является основой следующего этапа — детальной проработки доступа и аккаунта,
затем рабочих экранов. Здесь не проводятся полный редизайн страниц, миграция на Jinja2,
крупный рефакторинг или внедрение новых продуктовых функций.
