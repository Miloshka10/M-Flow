## Открыть

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -u design/workspace-prototype/serve.py
```

Просмотр: <http://localhost:5093/design/workspace-prototype/>. Сервер слушает только 127.0.0.1 и отдаёт только файлы макета и общий набор значков. Также можно открыть `index.html` непосредственно в браузере.

## Что можно попробовать

1. Переключать пять этапов. Ранее принятые результаты доступны; сдача будущих этапов закрыта, планирование задач доступно.
2. Смотреть дела всей команды или свои, искать, фильтровать по приоритету, исполнителю и сроку, менять сортировку; раскрывать выполненные и задачи без этапа.
3. Создать/отредактировать задачу, назначить исполнителя и этап, изменить статус; добавить отчёт по своей задаче. Удаление доступно только для задач без отчётов.
4. В роли ученика открыть доработку, сохранить черновик либо отправить повторно. Переключить роль на учителя, вернуть с обязательным замечанием или принять. Старые отправки и решения остаются в истории.
5. Посмотреть размещение команды, руководителя, защиты и результатов. Эти второстепенные панели поясняют существующие переходы, без реализации управления и оценивания.
6. Проверить аккаунт, мобильное меню, Escape, закрытие снаружи и возврат фокуса.

Макет автономный: все работы, имена, сроки и оценки придуманы; дата примера — 26 октября. Изменения хранятся только в памяти окна и сбрасываются при перезагрузке/смене примера. Нет запросов API, авторизации, подключения БД, сохранения в браузере или внешних ресурсов. Значки берутся из существующего `static/icon-symbols.css`. Переключение роли — демонстрация экранов, не проверка серверных прав.

## Интерфейсное решение

Один раздел «Работа над проектом» заменяет два соседних пункта «Задачи» и «Этапы». Общие сведения остаются в обзоре. Пять этапов образуют общий маршрут. Выбранный этап показывает цель и один основной следующий шаг. Слева — список дел, справа — результат, материалы и замечание/решение учителя. На телефоне маршрут и содержимое идут вертикально. Доработка обозначена текстом и янтарной поверхностью, проверка — текстом и кобальтом, принятие — текстом и зелёным. Выполненные задачи не принимают этап; принятая защита не публикует оценку автоматически.

Формы задач/результата открываются в боковой панели, на телефоне — на всю ширину. Сохранены цвета, системная типографика, текстовый логотип и текущие значки. Макет включает светлую и тёмную темы.

## Основа будущего переноса — после утверждения

Состояния и тексты сверены с `project_stages.py`, следующий шаг — с `project_workspace.next_step`, поля/фильтры/роли — с `task_board.py` и `TASK_BOARD.md`. Основная схема данных уже содержит `stage_number`, поэтому для предложенного объединения не требуется новая сущность этапа или новая загрузка файлов. Ссылки на материалы остаются в результате, презентация — в существующем поле.

| Часть | Существующая основа |
| --- | --- |
| Пять этапов, блокировки, доработка | `project_stages.get_stages`, `stage_label`, `stage_needs_revision`, `stage_summary` |
| Следующее действие | `project_workspace.next_step`, включая руководителя и отдельную защиту |
| Создание / редактирование задач | POST `/project/<id>/add`, `/project/<id>/edit/<task_id>` |
| Статус / приоритет / отчёты | POST `/project/<id>/status`, `/priority`, `/task/<task_id>/update` |
| Удаление | POST `/project/<id>/delete/<task_id>`, прежний запрет удаления с отчётами |
| Сдача и решения этапа | POST `/project/<id>/stages`, прежние `number`, `revision`, CSRF и проверки ролей |
| История | `work_history.py`, существующие неизменяемые отправки и решения |
| Команда, сопровождение, группы | Существующие страницы и согласование; доступ не выдаётся самим интерфейсом |
| Защита / личные оценки | `/project/<id>/defense`, `/assessment`, прежние проверки участников/личных оценок |

При переносе сохранить `/project/<id>/stages#stage-N`, `/project/<id>#task-board`, прямые ссылки на задачи, параметры фильтров и возврата формы. Старые входы должны открывать соответствующую часть общего пространства, сохраняя POST-обработчики, CSRF, optimistic locking и серверную проверку проекта/роли. Учитель читает задачи; владелец управляет ими; участник изменяет и отчитывается только по своим назначенным задачам. Прототипный `model.js` в серверную бизнес-логику не переносить.

## Фактически проверено

- 13 проверок модели макета: черновики, повторная сдача, снимки прошлых версий, обязательный комментарий, принятие, блокировка будущих/принятых этапов, отсутствие руководителя, презентация пятого этапа, независимость задач/этапов/защиты/оценок.
- В браузере: 128 сочетаний двух ролей, восьми примеров, двух тем и ширин 320/390/768/1440 px. По измерениям DOM горизонтального переполнения нет, на каждом экране пять этапов, учителю не показываются элементы изменения статуса задачи. [Результаты](browser-checks.json).
- Взаимодействия: создание задачи без этапа, отчёт, привязка к этапу, выполнение и сворачивание, фильтры и пустая выборка; сохранение черновика, повторная сдача, возврат и принятие с историей. Клавиатура: Tab/Shift+Tab в панели, Escape, восстановление фокуса, закрытие снаружи; состояния меню. [Записанная часть проверок](interaction-checks.json).
- Во время проверки исправлены фокус панели, подпись возвращённой работы, отделение старого замечания от новой проверки, содержание следующего действия и сообщения состояния аккаунта.

Команда тестов: `node --test design/workspace-prototype/model.test.cjs`.

Это проверка макета. Flask, серверные права, CSRF, PostgreSQL, production-сценарии и старые URL в этой работе не менялись и заново не тестировались. Подключение к реальным данным и регрессия приложения — следующий этап после оценки. На физических телефонах, в Safari/Firefox и с экранным диктором проверка не проводилась.
