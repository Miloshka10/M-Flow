# Защита аккаунтов и восстановление по email

Дополнение этапа 1: подготовлен Brevo HTTPS API наряду с SMTP TLS, проверка
конфигурации без вывода значений и доступа к базе, сценарий двух ролей с
перехваченными API-запросами и проверка ротации кода учителей. Реальной
отправки и новой визуальной проверки не было. Числа полного прогона ниже
относятся к предыдущей итерации; актуальные проверки отмечены в PR №12.
Условия закрытия и порядок подключения: [STAGE1_ACCESS.md](../../STAGE1_ACCESS.md).

31.10.2026. Продолжение коммита `889eb9a`, с учётом опубликованного дизайна
`2a011fb`. Рабочие данные и настройки Render/Neon не менялись.

## Результат

- Двойники новых логинов запрещены по общему Unicode-правилу на SQLite и
  PostgreSQL; исходные старые имена/роли сохранены. Неоднозначные старые варианты
  не выбирают случайный аккаунт. Инициализация учителя применяет ту же проверку.
- Подтверждение email, смена через оба ящика, одноразовое восстановление,
  отзыв сеансов и защита от повторного/одновременного применения ссылок.
- Новые письма не отправляются в HTTP-запросе; очередь ограничена. Все тестовые
  письма перехвачены локально, ни одного реального письма не отправлялось.
- Страница `/data` с фактическим описанием данных; без выдуманного оператора,
  адреса поддержки и фиктивного согласия.
- Первые защитные заголовки сохранены, HSTS поддерживает явно настроенный
  канонический HTTPS-хост без расширения доверия к прокси. Настройки оформления
  больше не используют встроенный `onsubmit`, `motion.js` загружается с `defer`.
- Новые таблицы входят в резервные копии и проверку восстановления.

Правила и настройка: [ACCOUNT_RECOVERY.md](../../ACCOUNT_RECOVERY.md).

## Проверки

- В полном локальном запуске: **691 тест, OK, пропущено 3**, SQLite + PostgreSQL 18.
  Отдельные новые сценарии повторены после последних небольших правок.
- Новая логика покрыта 18 сценариями в обеих базах: обычный путь, права, CSRF,
  неизвестный адрес, лимиты, просрочка, старый пароль, подмена назначения,
  одновременная регистрация/сброс и сохранность истории/ролей.
- Дополнительно проверены нормализация email, обязательное TLS SMTP, проверка
  сертификатов, ограничения очереди, скрытие диагностик, обработка fragment в JS.
- Все 12 JavaScript-наборов прошли.
- `server-http-checks.json`: полный путь подтверждения и восстановления обеих
  ролей дополнительно пройден через настоящий localhost HTTP-сервер с cookies,
  CSRF и перехватом писем. Это HTTP-проверка форм, не автоматизация браузера.
- Новой автоматизации браузера в этой сессии нет: прежний инструмент браузера
  недоступен. Серверные формы и HTTP/CSRF покрыты тестами, но это **не** повторная
  визуальная проверка двух тем и физических телефонов. Общий стиль сохранён.

## Аудит базы и рабочей версии

`historical-database-audit.json` содержит только схему/числа из двух старых
SQLite-объектов публичной Git-истории. Таблиц пользователей в них нет: одна
версия содержит проект и три задачи, другая — две задачи. Содержимое свободного
текста и удалённых SQLite-страниц не подвергалось полному forensic-аудиту;
это не заявление об отсутствии любых персональных данных во всей истории.
История Git не переписывалась.

Отдельный read-only аудит восстановленной локальной базы выполнен на копии
в памяти: 4 аккаунта, 0 групп совпадений, без вывода имён/паролей/хешей.
Проверка реальных логинов production не выполнялась.

`public-checks.json`: публичные `/health` и `/login` ответили 200. Первый запрос
занял 33.19 с, следующий — 0.44 с. Это два измерения, а не полноценный нагрузочный
тест. В проверенных ответах защитные заголовки ещё отсутствовали.

Render read-only: сервис `M-Flow-Minich`, бесплатный тариф, 1 instance,
автопубликация из `main` по коммиту, `healthCheckPath` не указан; live — `2a011fb`.
Настройки не менялись. По этим данным нельзя устанавливать доверенные CIDR:
общедоступный `ipAllowList` сервиса не является списком его входящих прокси.

## До рабочего выпуска

Нужны настоящий почтовый сервис/разрешённый отправитель, проверка доставки,
данные ответственного и контакт, заполненная политика и визуальная проверка
новых экранов. Бесплатный Render блокирует исходящие SMTP-порты 25/465/587
([ограничения тарифа](https://render.com/docs/free)); совместимость сервиса
отправки ещё не подтверждена. Адаптер Brevo HTTP API подготовлен, но аккаунт,
отправитель и доставляемость остаются непроверенными.
Доверенные сети прокси не угадывались. Ручной production-деплой,
миграции, платный тариф или «пинг от засыпания» не запускались.
