# Финальная ревизия интерфейса M-Flow

25–26 октября 2026. База изменений: `bc59202`, ветка `codex/interface-final-polish`.

## Исправлено

- Карточки и обложка ученика показывают фактическое состояние этапов и видеозащиты. Выполненные задачи больше не подменяют принятие проекта; при отсутствии задач нет вводящего в заблуждение «0%».
- Текущий проект выделен в списке. Переходы из проекта к списку и результатам сохраняют выбор. Возврат браузером из раздела по якорю восстанавливает активный пункт меню.
- Раздел «Мои проекты» существует и до создания первого проекта. Уведомления и руководство проектом получили правильные подписи вместо ложного выделения главной.
- Мобильное меню удерживает фокус среди видимых ссылок и кнопки закрытия, исключая перекрытый переключатель и фон. Панель сообщает модальное состояние; Escape возвращает фокус.
- Повышен контраст второстепенного текста в светлой теме, исправлен цвет текста кнопки создания проекта. Размер кнопок меню и уведомлений — не менее 44 px, текст аккаунта на узком экране увеличен.
- Цвета статусов согласованы между карточками и результатами. В кабинете учителя красным выделены только просроченные сроки. Добавлено выделение текущей вкладки защиты/оценивания.
- Уплотнена обложка проекта, уточнены отступы карточек. Страницы отказа в доступе и других ошибок оформлены в общей системе, получили основной ориентир `main`. Публичные настройки используют общий текстовый логотип.
- Убрано промежуточное бледное состояние активной боковой ссылки при смене раздела; настройки анимаций сохранены.

Схема данных, обработчики отправки/проверки, критерии, пять этапов, история, права и CSRF не менялись. Новое чтение состояний — один запрос на все доступные проекты; тексты работ и личные оценки для карточек не выбираются. Проверка постоянного количества запросов сохранена.

## Проверки на изолированных данных

- Полный набор на временной SQLite и локальном PostgreSQL: **546 тестов, OK, 3 условных пропуска**, 324,970 с. Все семь JavaScript-наборов прошли. После последнего упрощения пустых карточек повторены две серверные регрессии и проверка оболочки; финальная версия также проходит полный набор в CI перед объединением.
- Регрессии охватывают статусы этапов/защиты, несогласованные старые состояния, исключение чужих проектов, сохранение выбранного проекта, пустую главную, возврат активной навигации и цикл фокуса.
- [112 замеров браузера](browser-checks.json): обе роли, обе темы, 320/390/768/1440 px. Проверены главные страницы, проекты, этапы, оценивание, уведомления, руководитель и группа учителя. Во всех замерах один `main`, нет горизонтального переполнения, сломанных изображений или отсутствующих внутренних якорей. Это проверка разметки и загрузки, а не подтверждение всех действий на каждой странице.
- Дополнительно вручную: вход/POST-выход обеих ролей; первый проект с длинным названием; выбор проекта; фильтр опубликованной личной оценки (одна строка, 45/45); переход к результатам и Back; отказ 403 для чужого проекта без раскрытия названия; меню аккаунта, закрытие снаружи, Enter/Tab/Shift+Tab/Escape мобильного меню обеих ролей; отключение анимаций.
- Измеренный контраст проверенных светлых статусов: 4,97–5,90:1; пояснения на молочном фоне 5,26:1; белая надпись на синей кнопке создания 6,40:1. Это выборочная проверка, не полный аудит WCAG.
- В конце браузерной проверки журнал ошибок JavaScript пуст. Скриншоты ниже просмотрены вручную.

## Границы проверки

Все аккаунты и действия выше — синтетические, на временной локальной базе. Существующий полный набор проверяет отправку, возврат, повторную сдачу, принятие, историю, приглашения, группы, доступ и CSRF. В этой ревизии полный цикл сдачи вручную заново не повторялся: его браузерная проверка выполнена при выпуске 24 октября, обработчики не изменены.

На рабочем сайте после штатного Auto-Deploy проверяются только публичная доступность, вход/регистрация и загрузка версии ресурсов. Авторизованные рабочие сценарии на production не проверяются без разрешённого тестового доступа. Рабочие аккаунты, данные, настройки Render/Neon и ручные production-миграции не используются.

Физические телефоны, Safari/Firefox, скринридер и полный режим без JavaScript не проверялись. Эти результаты не означают отсутствия всех возможных ошибок. CI и текущий статус Auto-Deploy фиксируются отдельно при публикации, а не предполагаются из локальных проверок.
