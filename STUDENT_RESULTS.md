# Центр результатов ученика

Центр находится на существующей главной странице `/`, перед ближайшими задачами.
Это представление действующих данных, без новой таблицы, статусов или операций сохранения.
Кабинет учителя и формы проектов не заменяются.

- Источники: текущие строки `project_stages`, `project_defenses`, опубликованные
  `project_assessments` только самого ученика. Отчёты остаются информацией в задачах.
- Проекты доступны владельцу либо действующему участнику `project_members`.
  Параметр URL не даёт доступ к проекту. Оценки других участников и черновики
  учителя не выбираются. Историческая опубликованная личная оценка сохраняется
  при смене руководителя, пока ученик имеет доступ к самому проекту.
- Доработка этапа определяется существующим `stage_needs_revision`-условием
  (состояние `progress` и `reviewed_by`), не наличием текста комментария.
  Для новой сдачи прежний комментарий помечен как относящийся к предыдущей версии.
- Следующий шаг рассчитывает существующая `project_workspace.next_step`.
  Ссылки ведут в действующие формы с их серверными проверками доступа, CSRF,
  актуальности версии и состояния. GET не проверяет работу и не читает уведомления.
  Новые уведомления этапов ведут к `#stage-N`; старые ссылки получают этот якорь
  при отображении по проверенному ключу события, без изменения сохранённых записей.
- Фильтры URL: `result_project`, `result_state`, `result_page`. Некорректный проект
  даёт 400, недоступный — 403; неверное состояние/страница нормализуются.
  Сортировка: доработка, проверка, черновики, принятые результаты, оценки;
  внутри групп стабильный порядок по проекту, типу и номеру. Это не хронология.
- Пагинация по 12 элементов применяется в SQL. Два запроса: количества и страница;
  ещё три пакетных запроса для следующего шага только проектов текущей страницы.
  В карточки не выводятся тексты самих работ. Для существующего расчёта следующего
  шага читаются не более пяти этапов каждого показанного проекта, с исходным
  текстом черновика (чтобы сохранить правила проверки пустого ввода). Количество запросов не зависит
  от числа результатов. Существующий список проектов/задач главной не менялся.
- Даты отображаются в Москве (UTC+3). Для актуальной сдачи на проверке известна
  дата отправки, для принятого результата — решения; после правок возвращённого
  этапа есть только дата последнего обновления. Отдельную дату прежней проверки
  схема не хранит, поэтому она не восстанавливается предположением. Некорректные
  и отсутствующие даты обозначаются явно. У оценки подписано время обновления.

## Безопасная проверка

`tests/results_cases.py` входит в общие SQLite/PostgreSQL-тесты. PostgreSQL
допускается исключительно на localhost в одноразовой схеме `mflow_test_*`;
CI использует отдельный PostgreSQL 18, не Neon.

Для браузера: `.venv/Scripts/python.exe tests/preview_notifications.py --results`.
Только loopback `127.0.0.1:5091` и временная SQLite. Аккаунты `preview-student`,
`preview-engineer` и `preview-teacher`, тестовый пароль `preview-only-123`.
Остановить Ctrl+C; временная база удаляется штатно. Данные полностью синтетические.
На рабочей базе этот сценарий не запускать.
