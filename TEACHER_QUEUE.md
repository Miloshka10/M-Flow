# Очередь работ учителя

Очередь находится в существующем кабинете `/teacher#review-queue` и строится
из существующей сводки. Новых таблиц, состояний, фонового опроса и миграций нет.

- Решения требуют только текущий этап в состоянии `review` и видеозащита
  `submitted`. Принятые, черновые и возвращённые результаты в эту группу не входят.
- Повторная сдача отображает текущую строку и её версию, не историю уведомлений.
- Отчёты — информационная группа: последний по ID отчёт каждой задачи. У них
  нет состояния проверки или «Принят». Прочитанное уведомление не скрывает
  результат и не заменяет решение учителя.
- Дата берётся из `updated_at` отправленного этапа/видеозащиты или `created_at`
  отчёта. Для ожидающей проверки строки последнее изменение является сдачей:
  до решения учителя результат нельзя редактировать. Отдельная дата задним
  числом не создаётся. Пустые/невалидные даты обозначаются явно и идут в конце
  группы в обоих направлениях сортировки.
- SQLite-наивные даты интерпретируются как UTC; PostgreSQL-смещение сохраняется
  при разборе. Отображение — Москва (UTC+3), сортировка — по абсолютному времени.
- Сначала результаты, требующие решения, затем информация. В каждой группе
  по умолчанию самые ранние сдачи; равные даты имеют стабильный порядок.

GET-параметры одной существующей формы:

| Параметр | Смысл |
| --- | --- |
| `q` | Поиск проекта, участника/автора или названия работы; до 100 символов |
| `focus` | Существующее состояние проектов, включая просроченные задачи |
| `project` | Один доступный проект; отсутствующий/пустой — все |
| `kind` | `all`, `stage`, `defense`, `report`; влияет только на очередь |
| `sort` | `oldest`, `newest`; порядок дат внутри групп очереди |
| `page` | Страница очереди по 20 пунктов |

Неверные `kind`, `sort`, `focus` нормализуются к значениям по умолчанию.
Неверная/неположительная страница становится первой; слишком большая —
последней. Некорректный ID проекта даёт 400, недоступный — одинаковый 403 без
раскрытия существования проекта. Ссылки страниц сохраняют остальные фильтры.
Изменение фильтра сбрасывает страницу. Общие показатели учитывают все проекты
учителя, а число найденных работ — текущие фильтры.

Сроки и назначение задач остаются в соседнем блоке, не внутри очереди сдач.
Просрочка задачи ученика не становится просрочкой проверки учителя.

Объём вывода очереди ограничен 20 пунктами. Источник — уже существующая
пакетная сводка: она всё ещё загружает все доступные проекты и их данные, а
пагинация выполняется в памяти. Это **не** SQL-пагинация всей сводки. Число
SQL-запросов не растёт от количества проектов или пунктов очереди; новая
очередь дополнительных запросов не добавляет. Для масштабов с тысячами
проектов потребуется отдельная оптимизация всей сводки, а не только очереди.

Права повторно проверяются на странице результата и при сохранении, старые
ссылки не дают доступ после удаления учителя из проекта. Чтение очереди не
меняет пользовательские записи, уведомления или результаты.
