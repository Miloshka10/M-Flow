# M-Flow

M-Flow — веб-приложение для учителя и учеников: проекты, Kanban-доска, дедлайны, приоритеты, персональное назначение задач и кабинет учителя.

## Возможности

- отдельные вход и регистрация для учителя и ученика, смена пароля в профиле;
- создание проектов и добавление участников;
- назначение задач ученикам, редактирование срока и ответственного;
- отчёты учеников по назначенным задачам с историей записей;
- статусы «Новые», «В работе», «Готово» (drag-and-drop);
- подсветка и список «горящих» дедлайнов;
- **кабинет учителя** (`/teacher`): сводка по всем проектам, прогресс каждого ученика, просроченные задачи и задачи без ответственного с быстрым исправлением.
- поиск проектов по названию или логину ученика, фильтры состояния, последние отчёты и создание проекта прямо в кабинете;
- учитель видит проекты, которыми владеет или в которых состоит участником; менять задачи может владелец проекта.

## Интерфейс

Обновлён дизайн в спокойной бирюзовой палитре: единая сетка, отступы, поля, кнопки и карточки для кабинета, задач, этапов и оценивания. Удалены конфликтующие синие и жёлто-чёрные слои оформления. Общая тема находится в `static/mflow-theme.css`; стили отдельных функций используют её переменные.

На входе и регистрации форма размещена слева, а справа — название M-Flow и подпись «by Minich» с медленным переливом текста. На телефонах форма остаётся первой, брендовый блок располагается ниже. Анимация отключается при настройке устройства «уменьшить движение»; сохранены фокус клавиатуры и поддержка режима повышенного контраста. Внешние шрифты и изображения не загружаются.

## Команды из учеников разных классов

Добавлены учебные профили (`/skills`): класс, направление, до 12 навыков и короткое описание. Ученик открывает их из своего профиля или раздела «Команды» и сам включает показ в каталоге. По умолчанию учебный профиль не опубликован. Каталог доступен только вошедшим пользователям; учебные данные скрытого профиля не показываются ни в поиске, ни на странице команды. Логин и командная роль участника по-прежнему видны его команде.

В разделе «Команды» (`/teams`) можно искать по навыку, направлению, классу и свободному тексту. Класс не ограничивает участие: ученик ИТ-класса может работать с учеником инженерного класса. Команда — это участники одного проекта, а не отдельный дубликат проекта. Владелец проекта (учитель или ученик) отправляет приглашение с ролью и сообщением. Приглашённый видит его в разделе «Команды» и принимает или отклоняет; до принятия доступ к проекту не выдаётся. Профили и навыки заполняются самими учениками, их уровень системой не подтверждается.

Страница `/project/<id>/team` показывает состав и роли. Владелец может изменить роль или отменить ожидающее приглашение. Удаление участников осталось на доске проекта. Назначать задачи принявшим приглашение ученикам можно обычным способом. Старое добавление по известному логину сохранено для владельцев проектов, в том числе для подключения учителя к ученическому проекту.

Отключение каталога скрывает учебный профиль, но не отменяет существующие приглашения и членство в командах. Принятые приглашения и роли сохраняются в базе; при удалении участника из проекта его командная роль удаляется автоматически.

## Видеозащита проекта

Добавлена запись защиты по ссылке (`/project/<id>/defense`). Ссылка «Видеозащита» есть на доске и в кабинете учителя. Ученик — участник проекта — сохраняет ссылку и описание в черновик, затем отправляет учителю. Учитель — владелец или участник проекта — принимает защиту либо возвращает её с обязательным комментарием. После возврата команда может заменить запись и отправить повторно. Во время проверки и после принятия редактирование записи заблокировано; устаревшие формы не перезаписывают изменения коллег.

Хранится одна текущая запись на проект; история её замен не ведётся. Черновик и результат проверки видны участникам проекта, не всему каталогу. Защита не меняет пять этапов или баллы по критериям автоматически.

Это не видеозвонок и не загрузка видео на Render: подходят HTTP(S)-ссылки на видеосервис или облачный диск. Видео открывается по нажатию; внешние плееры не встраиваются и ссылки сервером не загружаются. Доступность записи и права просмотра нужно проверить самостоятельно. Не указывайте в ссылке логин и пароль. Доступ к видео на внешнем сервисе определяется его настройками, а не правами проекта M-Flow.

Таблицы профилей, приглашений, командных ролей и видеозащиты создаются при старте без удаления существующих данных; новые команды запуска не требуются.

## Пять этапов работы над проектом

Добавлены общие для участников проекта этапы:

1. Выбор темы и согласование с учителем.
2. Работа над проектом — 1.
3. Работа над проектом — 2.
4. Работа над проектом — 3.
5. Подготовка документации: презентация и описание проекта.

Открыть этапы можно с доски проекта или из кабинета учителя (`/project/<id>/stages`). Ученик сохраняет черновик результата и отправляет его на проверку. Учитель — владелец или участник проекта — согласовывает тему, принимает этапы или возвращает результат на доработку с обязательным комментарием. Следующий этап открывается только после принятия предыдущего. На пятом этапе обязательны текст описания проекта и полная HTTP(S)-ссылка на презентацию; файл презентации хранится во внешнем сервисе и должен быть доступен учителю по ссылке.

Прогресс этапов отображается отдельно от выполнения задач и итоговой оценки. Этапы общие для проекта, а не персональные для каждого ученика. Чужие проекты недоступны; формы защищены от подделки запросов и перезаписи устаревшей вкладкой. Принятые этапы нельзя изменить. История версий черновиков не ведётся.

Таблица `project_stages` создаётся автоматически при старте. Новые и существующие проекты получают пять этапов без изменения задач, отчётов и оценок. Существующие проекты начинают с первого этапа: завершение задач не означает автоматического согласования темы.

## Оценивание проектов

Добавлено оценивание по ведомости проектов 10–11 классов: 12 критериев, максимум 45 баллов. В кабинете учителя у каждого проекта есть ссылка «Оценивание»; такая же ссылка доступна на доске проекта.

Учитель выбирает ученика, указывает ФИО, выставляет целые баллы по критериям и оставляет примечание. Незаполненный критерий отличается от нулевого балла. Черновики можно сохранять частично; для публикации нужны все 12 критериев. Итоговая оценка рассчитывается автоматически: «5» — 39–45, «4» — 30–38, «3» — 21–29, «2» — 0–20 баллов (точные границы из ведомости).

Оценивать может учитель — владелец или участник проекта. Каждый учитель сохраняет собственную оценку, не перезаписывая оценки коллег. Ученик видит только свои опубликованные оценки. Повторное сохранение обновляет оценку; история версий не ведётся. Сохранение опубликованной оценки как черновика скрывает её от ученика.

Таблица `project_assessments` добавляется автоматически при старте приложения; существующие данные сохраняются. Новые переменные окружения и команды запуска не нужны. На Render для сохранения оценок между развёртываниями, как и остальных данных, необходим постоянный диск с `M_FLOW_DATABASE`.

## Мобильная версия

Добавлена адаптивная раскладка для телефона без отдельного адреса сайта. Навигация, формы, доска задач и карточки перестраиваются по ширине экрана. Таблицы критериев оценивания и прогресса учеников на узком экране отображаются как записи с подписями полей. Учтены безопасные отступы экрана и крупные элементы управления; поля ввода на телефоне используют шрифт 16 px.

Статус задачи можно изменить выпадающим списком в карточке без перетаскивания. Управление доступно владельцу проекта и ответственному за задачу; серверные проверки прав сохранены. Перетаскивание на компьютере также поддерживается.

Проверены основные страницы в браузере при ширине 320, 390, 430, 768 и 1280 px, страницы входа и регистрации — также при 844 px. Это проверка размеров браузера, не тест на физических устройствах. После публикации обновите страницу телефона; если браузер включает «Версию для ПК», отключите её. Новые настройки сервера или изменения базы данных не нужны.

## Анимации интерфейса

Добавлено единое оформление ссылок-действий: рамка, фон, скругление, подсветка при наведении и область нажатия не меньше 44 px. Оформлены навигация, возврат назад, переходы к разделам проекта, сброс фильтров, открытие презентации, вкладки входа/регистрации и раскрытие отчётов. Светлая и тёмная темы используют общие цветовые переменные; обычные ссылки внутри текста не превращаются в кнопки.

Добавлено спокойное перемещение подсветки только между кнопками «Я ученик / Я учитель»: страница и форма не двигаются и не исчезают. Переход выполняется после короткого движения индикатора (220 мс). «Вход / Регистрация» работают как обычные ссылки. Кнопки и ссылки получили единые короткие эффекты нажатия и плавные изменения цвета. Поля ввода плавно подсвечиваются при фокусе. Отправка форм и обычные переходы по сайту не задерживаются.

При системной настройке уменьшения движения или отключении анимаций в настройках сайта эффекты отключаются. Без JavaScript страницы входа и регистрации остаются обычными рабочими ссылками. Анимация не сохраняет данные формы и не использует хранилище. Возврат кнопкой браузера «Назад» не оставляет переключатель заблокированным.

## Настройки сайта

Добавлена страница `/settings`: светлая, тёмная или системная тема, включение анимаций и сброс к стандартным настройкам. Открыть её можно из навигации, профиля и страниц входа/регистрации, в том числе без аккаунта. Системная тема отслеживает изменения оформления устройства.

Выбор применяется сразу и хранится в `localStorage` этого браузера для всего сайта, а не в аккаунте. Между устройствами настройки не синхронизируются. Если хранилище браузера недоступно, настройки работают на текущей странице, но не сохраняются; об этом выводится сообщение. Возврат назад и другие вкладки учитывают сохранённые изменения. Настройки не меняют базу данных, проекты, роли или пароли.

## Проверка функций

### Оптимизация запросов и загрузки страниц

Оптимизирована главная: показатели проектов считаются одним запросом, без загрузки всех карточек каждого проекта. В кабинете учителя задачи, участники, этапы, видеозащиты и последние отчёты загружаются пакетно только для доступных проектов. Полная история отчётов на доске сохранена. Добавлен индекс `task_updates(task_id, id DESC)` для поиска последнего отчёта; он создаётся автоматически при запуске без удаления данных.

Текущий пользователь загружается один раз за HTTP-запрос, не сохраняется между запросами или аккаунтами. Права при отрисовке карточек определяются из уже загруженных данных; изменяющие запросы по-прежнему отдельно проверяют права на сервере.

Локальный замер на отдельной временной SQLite-базе: 42 доступных проекта, 803 задачи, пять загрузок каждой страницы. Время — медиана серверной обработки через Flask test client, без сети, браузера и холодного старта хостинга; это не обещание такой же скорости на Render.

| Страница | SQL-запросы до → после | Время до → после |
| --- | --- | --- |
| Главная | 46 → 2 | 20,39 → 1,73 мс |
| Кабинет учителя | 213 → 7 | 71,25 → 4,80 мс |
| Доска с 20 задачами | 51 → 8 | 19,56 → 4,20 мс |

Повторить замер: `python tests/benchmark_queries.py` из корня репозитория (с установленными зависимостями). Скрипт не использует рабочую базу. Добавлены тесты постоянного числа запросов при росте проектов/карточек, изоляции пользователей, последних отчётов и агрегированных показателей. Хостинг, дизайн и настройки публикации не изменены; задержку запуска спящего сервера эта оптимизация не устраняет.

После финальной ревизии добавлены проверки неверных JSON-запросов, слишком больших номеров записей, завершённой сессии, ограничения размера запросов и безопасного старого скрипта инициализации. Статус и приоритет больше не вызывают 500 из-за неверного типа входных данных. Изменение статуса обновляет общие показатели проекта и прогресс учеников, даже если доска отфильтрована. При ошибке сети карточка остаётся в прежней колонке.

Логика доски вынесена из большого HTML-блока в `static/kanban.js`. Удалена дублирующая схема и принудительное создание демо-данных из `init_db.py`; совместимая команда использует штатную инициализацию приложения и `M_FLOW_DATABASE`. Пользовательские данные не удаляются и владельцы проектов не переназначаются. Для production, как и при запуске приложения, нужен `M_FLOW_SECRET_KEY`. В `.gitignore` добавлены локальные базы, служебные файлы SQLite и `.env`.

Приоритеты следующего дня и готовые промпты: [NEXT_STEPS.md](NEXT_STEPS.md). Проверки локальные; реальное развёртывание, журналы ошибок Render и резервное копирование отдельно не проверены.

```powershell
python -m unittest discover -s tests -v
node tests/test_motion.cjs
node tests/test_preferences.cjs
node tests/test_kanban.cjs
```

Проверки используют отдельную временную базу данных.

## Аккаунты учеников и учителей

- Ученики: регистрация `/register`, вход `/login`.
- Учителя: регистрация `/teacher/register`, вход `/teacher/login`.

На каждой странице есть переключатель «Я ученик / Я учитель». Учитель выбирает свой логин и пароль при регистрации и сразу попадает в кабинет. Имя `uchitel2` не требуется. Роль определяется страницей регистрации; вход выполняется через страницу своей роли. Существующие аккаунты учителей доступны через `/teacher/login` с прежними данными.

У новых учителей отдельное рабочее пространство. Учитель видит только свои проекты и проекты, в которые его добавили участником.

## Локальный запуск

```powershell
python -m pip install -r requirements.txt
$env:M_FLOW_DEBUG = "1"
python -m flask --app app run
```

В режиме `M_FLOW_DEBUG=1` создаются демо-аккаунты `uchitel` / `1234` (учитель) и `milosh` / `1234` (ученик). Без этого режима они не создаются.

## Публикация (Render)

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `M_FLOW_SECRET_KEY` | **обязательна**, длинная случайная строка; без неё приложение не запустится |
| `M_FLOW_TEACHER_USER`, `M_FLOW_TEACHER_PASSWORD` | необязательны: создают начальный аккаунт учителя при старте (пароль от 8 символов); остальные учителя регистрируются через сайт |
| `M_FLOW_DATABASE` | путь к SQLite, например `/var/data/database.db` (на persistent disk) |

Команда запуска: `gunicorn app:app` (`init_db.py` больше не нужен, таблицы создаются при старте).
