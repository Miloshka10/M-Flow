# Почта и восстановление доступа

## Как работает

1. Вошедший пользователь открывает «Профиль → Почта и восстановление», вводит
   адрес и текущий пароль. Письмо подтверждает владение ящиком. Пока адрес не
   подтверждён, восстановление через него запрещено.
2. При смене уже подтверждённой почты нужны отдельные подтверждения старого
   и нового ящиков. До обоих подтверждений действует старый адрес. Повторная
   заявка делает прежние подтверждения недействительными.
3. «Забыли пароль?» запрашивает логин и подтверждённый email. Ответ одинаков
   для подходящих и неподходящих данных; отправка выполняется вне HTTP-запроса.
4. Одноразовая ссылка сброса действует 20 минут, подтверждение почты — 24 часа.
   Смена пароля отзывает все старые сеансы, все ссылки восстановления и
   незавершённую смену почты. Автоматического входа после сброса нет.

Ни учитель, ни владелец проекта не получает право сбрасывать чужой пароль.
Для старых аккаунтов адрес не угадывается и не назначается автоматически.
Если пользователь уже потерял пароль и раньше не подтвердил email, этот путь
ему недоступен: потребуется отдельная проверка личности организатором. Общего
«пароля администратора» и обхода подтверждения здесь нет.

Несколько аккаунтов могут подтвердить один семейный ящик: поэтому запрос
восстановления требует и логин, и email. Нормализуется регистр адреса; точки и
`+метки` не удаляются. Международные домены поддерживаются через IDNA, local-part
адреса — обычный ASCII; адреса EAI и quoted local-part не поддерживаются.

## Подключение почты

SMTP — служба отправки писем с адреса приложения. Нужен предоставленный
организатором почтовый сервис с разрешённой отправкой служебных писем. Создание
аккаунта провайдера, оплата, настройка домена и ввод секретов не выполнялись.

Для текущего бесплатного Render есть отдельное ограничение: исходящие порты
25, 465 и 587 закрыты ([документация Render](https://render.com/docs/free)).
Обычные настройки SMTP на 465/587 на этом тарифе не подойдут. Подготовлен
дополнительный транспорт Brevo HTTPS API с фиксированным адресом
`https://api.brevo.com/v3/smtp/email`, стандартным HTTPS-портом и проверкой TLS.
Это вариант подключения, а не созданный аккаунт или проверенная доставка.
SMTP с обязательным TLS сохраняется. Тариф и сетевые настройки не менялись.

Выбор явный: `M_FLOW_MAIL_PROVIDER=smtp` (по умолчанию), `brevo` либо `emailjs`.
При ошибке конфигурации или ответа нет автоматического перехода на другой
способ отправки. API-ключ никогда не попадает в браузер; перенаправления
HTTP запрещены, тело ответа провайдера не выводится. Ответ 201 означает приём
запроса провайдером, а не получение письма пользователем.

Приложение читает переменные процесса; `.env.example` — только справочник,
автоматической загрузки `.env` нет.

| Переменная | Назначение |
| --- | --- |
| `M_FLOW_PUBLIC_URL` | Канонический HTTPS origin сайта, без пути, query и пароля; не берётся из `Host` запроса |
| `M_FLOW_MAIL_PROVIDER` | `smtp`, `brevo` либо `emailjs`; неизвестное значение закрывает отправку |
| `M_FLOW_MAIL_API_KEY` | Ключ Brevo API либо Private Key EmailJS; это не SMTP-ключ |
| `M_FLOW_MAIL_PUBLIC_KEY` | Public Key EmailJS; в этом подключении также хранится только на сервере |
| `M_FLOW_MAIL_SERVICE_ID` | Сохранённый сервис EmailJS |
| `M_FLOW_MAIL_TEMPLATE_ID` | Сохранённый шаблон EmailJS |
| `M_FLOW_MAIL_HOST` | SMTP-сервер выбранного почтового сервиса |
| `M_FLOW_MAIL_PORT` | Обычно 587 для STARTTLS, 465 для TLS с начала соединения |
| `M_FLOW_MAIL_TLS` | `starttls` (по умолчанию) или `ssl`; незашифрованного режима нет |
| `M_FLOW_MAIL_USER` | Учётная запись отправителя |
| `M_FLOW_MAIL_PASSWORD` | Секрет SMTP; только закрытые настройки хостинга |
| `M_FLOW_MAIL_FROM` | Разрешённый провайдером адрес отправителя |

Для `brevo` нужны только `M_FLOW_MAIL_PROVIDER`, `M_FLOW_PUBLIC_URL`,
`M_FLOW_MAIL_FROM`, `M_FLOW_MAIL_API_KEY`; поля SMTP не используются.
Нужно отдельно подтвердить отправителя, разрешённость использования сервиса,
настройки хранения писем и поведение ссылок/отслеживания у провайдера.
API отправляет только служебное текстовое письмо; списки контактов и подписки
приложение не создаёт. Провайдер получает получателя, логин и ссылку из письма.

Для `emailjs` дополнительно нужны Public Key, Service ID и Template ID;
Private Key обязателен. Контракт шаблона, отключение истории параметров и
ограничения малого пилота описаны в [EMAILJS_SETUP.md](EMAILJS_SETUP.md).
API получает текст и отдельную кнопку только из полной доверенной строки ссылки.
Чужой URL в логине не может стать этой кнопкой. В браузерные скрипты ключи не входят.

EmailJS ограничивает отправку одним запросом в секунду. Задания диспетчера
координируются через короткую общую аренду в существующей `auth_limits`:
транзакция закрывается до сети, после отправки остаётся двухсекундный интервал.
Запись содержит только HMAC идентификатора аккаунта, номер аренды и срок.
Без подключённого ограничения диспетчер не отправляет через EmailJS.
Ожидание задания ограничено; отдельного фонового опроса без писем нет.
API самостоятельно отправленные запросы из кабинета и других приложений эта
координация не контролирует. Новая миграция/таблица для неё не требуется.

Если конфигурация отсутствует/некорректна, восстановление и привязка почты
показывают понятное недоступное состояние. POST не сообщает о несуществующей
отправке. Вход и обычная смена пароля по текущему паролю остаются доступны.
Отправка с реального адреса на реальный ящик и доставляемость сейчас **не проверены**.

## Защита и ограничения

- POST требует CSRF. GET ссылки ничего не подтверждает и не меняет пароль.
- Токены — 32 случайных байта, в базе хранится HMAC. Они привязаны к версии
  пароля и ревизии почты; старые ссылки не оживают после изменения аккаунта.
- Секрет ссылки передаётся в `#fragment`, который не отправляется веб-серверу.
  Отдельный скрипт переносит его в форму и очищает URL через `replaceState`.
  При отключённом JS можно скопировать код из того же письма в обычную форму.
  На страницах восстановления установлен `Referrer-Policy: no-referrer`.
- Запрос письма ограничен 3 попытками за 15 минут на адрес/назначение и
  10 на браузер/источник; отказ не продлевает окно. Подтверждение и сброс имеют
  отдельные лимиты. Пароль для изменения почты дополнительно ограничен по аккаунту.
- Очередь отправки ограничена 16 заданиями и двумя потоками, не опрашивает сервер
  в фоне и не требует отдельного платного сервиса M-Flow. HTTP-запрос не ждёт SMTP.
  Задания в памяти могут потеряться при перезапуске процесса; пользователь может
  повторить запрос. Ошибки доставки логируются без адресов, токенов и ответов провайдера.
- Таблица токенов ограничена 20 000 записями; просроченные очищаются порциями.
  Слишком много записей не отключает защиту, а даёт временный отказ.
- Персональные оценки, роли, права, проекты и история при сбросе не меняются.
- Таблицы `account_emails` и `account_email_tokens` создаются при обычном старте;
  пользовательские записи не переименовываются и не получают выдуманную почту.
  Копии включают обе таблицы. Восстановление старой резервной копии может вернуть
  старые токены/сессии; после инцидента нужна отдельная процедура отзыва секретов.

Подход сверялся с [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
Это не заявление о полном аудите безопасности или доставляемости писем.

## Логины

Новые логины сравниваются по Unicode NFKC + `casefold` под прежней общей
блокировкой авторизации. `Ivan`, `ivan` и совместимые Unicode-варианты не могут
создать новые разные аккаунты. Инициализация учителя следует тому же правилу.
На небольшой школьной базе проверка читает только имена; дополнительной
миграции уникальности и слияния аккаунтов нет. Записи вне приложения прямым
SQL обходят эту проверку; инструменты импорта должны применять то же правило.

Старые точные логины сохраняют доступ к своим аккаунтам. Если исторически
есть совпадение, неоднозначный вариант не выбирает случайного пользователя.
Лимиты входа используют тот же ключ имени. Это не полная защита от всех
визуально похожих символов разных алфавитов.

Read-only аудит локальной SQLite на копии в памяти, без импорта приложения:

```powershell
.\.venv\Scripts\python.exe audit_accounts.py --sqlite ПУТЬ_К_КОПИИ.db
```

Выводятся только числа аккаунтов и групп совпадений, без логинов/паролей/хешей.

## Данные и помощь

Страница `/data` описывает фактические данные и доступ. `M_FLOW_OPERATOR_NAME`
и `M_FLOW_SUPPORT_EMAIL` позволяют указать настоящего ответственного и контакт.
Сейчас они неизвестны: не добавлены фиктивная организация, email или чекбокс
согласия. Страница явно не выдаётся за завершённую юридическую политику.
Реквизиты, сроки хранения, порядок удаления и требуемые согласия надо определить
до использования с реальными учениками.

## Перед публикацией

Проверка конфигурации без сети, импорта приложения и открытия базы:

```powershell
.\.venv\Scripts\python.exe check_account_setup.py
```

Выводятся только имена недостающих переменных и признаки наличия/валидности.
Код возврата 1 означает незавершённую конфигурацию. Даже код 0 не подтверждает
доставку, полномочия учителей, законность обработки или готовность выпуска.
Операционный список этапа: [STAGE1_ACCESS.md](STAGE1_ACCESS.md).

1. Проверить CI именно публикуемого коммита и включённые изменения дизайна.
2. Подтвердить выбранный почтовый сервис, доступность его HTTPS API либо
   TLS-порта, настроить отправителя/домен и закрытые переменные.
3. На разрешённой тестовой среде проверить доставку, одноразовость и срок ссылок.
4. Определить ответственного, контакт, сроки хранения и порядок обращений.
5. Проверить реальную цепочку прокси и HTTPS/HSTS, не доверяя произвольному XFF.
6. Учесть, что код регистрации учителя и конфигурация почты — разные настройки.
   Никакие production-миграции вручную и ручной деплой в этой работе не запускались.
