# Отображение сроков

Срок хранится только в `tasks.deadline`: календарная дата `YYYY-MM-DD`, без времени.
У проектов и пяти этапов собственных сроков нет. Новые поля и сроки не добавлены;
даты в существующих записях не изменяются при просмотре.

Единый расчёт — `deadlines.py`. День определяется по Москве (UTC+3) независимо от
часового пояса Render и телефона. Срок действует до конца указанного дня: сегодня
ещё не просрочено, с наступлением следующего календарного дня — просрочено на один день.
Подпись содержит относительное состояние и точную дату. Завершённая задача сохраняет
точную дату, но не получает предупреждение. Пустой срок отображается как «Без срока»;
повреждённая дата — «Срок некорректен», без попытки исправить пользовательские данные.

## Где отображается

- Главная ученика: до шести ближайших незавершённых задач, назначенных ему или
  не назначенных никому, только из доступных проектов. Просроченные — первыми.
  Показатели проектов по-прежнему относятся ко всем задачам команды.
- Доска: подписи всех задач, список просроченных и ближайших (включительно три дня).
  После смены статуса сервер возвращает новые подписи, счётчики и список;
  JavaScript не вычисляет даты по часовому поясу устройства.
- Кабинет учителя: «Просрочены задачи учеников» и «Ожидают моей проверки» — разные
  фильтры. Ожидание проверки этапа/видеозащиты само по себе не является просрочкой.
  Принятые этапы не создают предупреждений: у этапов нет срока.

## Фильтры и сортировка доски

GET-параметры: `q` (поиск, до 100 символов), `priority`, `mine=1` (только ученику),
`due` (`overdue`, `today`, `tomorrow`, `week`, `none`) и `sort` (`priority`, `deadline`).
Неизвестные значения игнорируются, сортировка возвращается к приоритету.
Форма сохраняет сочетания параметров в URL и возвращает к доске после отправки.

`week` включает сегодня и седьмой день; просроченные — только в отдельном фильтре.
Завершённые задачи исключены из активных фильтров сроков. `none` включает только
пустые даты, а не повреждённые; завершённая задача без даты тоже может попасть сюда.
Сортировка по сроку — от раннего к позднему, затем пустые/некорректные даты;
при равенстве — по ID, без влияния приоритета. Три колонки статусов сохранены.
Показатели проекта относятся ко всем задачам, счётчики колонок — к выбранным.
Список ближайших сроков доски ссылается только на видимые карточки.

Вся фильтрация и сортировка выполняется над уже загруженными задачами, без новых
запросов. При любом активном фильтре или сортировке по сроку изменение статуса/
приоритета перезагружает текущий URL только после успешного ответа сервера. На
доске без фильтров с сортировкой по приоритету остаётся обновление без перезагрузки.

Сроки не обновляются фоновым опросом: после полуночи нужна загрузка страницы или
смена статуса задачи. Главная добавляет один пакетный запрос для всех доступных
проектов, кабинет и доска используют уже загруженные задачи; запросов на карточку нет.

## Проверка

`python -m unittest discover -s tests` и `node tests/test_kanban.cjs` проверяют
календарные границы, високосный год, отсутствие/некорректность даты, завершение и
повторное открытие, фильтры, права, экранирование, неизменность данных при GET и
постоянное число запросов. Интеграционные проверки из `test_teacher_cabinet.py`
наследуются PostgreSQL-набором CI на отдельной локальной базе, не Neon.

Для ручной проверки: `python tests/preview_notifications.py --deadlines` запускает
локальный сервер на 127.0.0.1:5091 с временной SQLite-базой. Тестовые логины
`preview-student` / `preview-teacher`, пароль `preview-only-123`; не использовать в production.
