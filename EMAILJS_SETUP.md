# Служебные письма M-Flow через EmailJS

Этот вариант предназначен для проверки и небольшого пилота: EmailJS принимает
HTTPS-запрос от сервера M-Flow и отправляет письмо через подключённый Gmail.
Отдельный домен для такого подключения не требуется. Подключение сервиса и
ответ API сами по себе не доказывают, что письмо пришло получателю.

## 1. Подключить почтовый сервис

1. В кабинете EmailJS открыть **Email Services** и добавить Gmail.
2. Подключить управляемый организатором ящик, предназначенный для M-Flow.
   Пароль Gmail не вводится в код M-Flow и не отправляется в чат.
3. Сохранить сервис и его **Service ID**. Для отправки приложением нужен
   именно сохранённый сервис, а не только созданный аккаунт EmailJS.

Личная почта подходит для разработки и очень малого объёма. EmailJS рекомендует
транзакционный почтовый сервис для production-нагрузки. Это подключение не
является обещанием надёжной массовой отправки всему школьному классу.
[Официальное руководство](https://www.emailjs.com/docs/user-guide/connecting-email-services/).

## 2. Разрешить серверные запросы и защитить их

В **Account → Security** включить API-запросы для серверных/non-browser
приложений и авторизацию **Private Key**. Если настройки уже включены,
повторно создавать или менять ключ без причины не нужно.

Все вызовы EmailJS выполняются Flask-сервером. Public Key в этой интеграции
тоже хранится на сервере; в JavaScript страницы ничего переносить не требуется.
Private Key обязателен для выбранного подключения, хотя сам API допускает
его отсутствие при других настройках аккаунта.
[Настройки ключей](https://www.emailjs.com/docs/sdk/options/),
[пояснение серверного доступа](https://github.com/emailjs-com/emailjs-nodejs).

## 3. Создать один шаблон

Открыть **Email Templates**, создать шаблон и задать поля:

| Поле | Значение |
| --- | --- |
| To Email | `{{to_email}}` |
| Subject | `{{subject}}` |
| From Name | `M-Flow` |
| From Email | Адрес подключённого Gmail/default сервиса; если предложено использование адреса по умолчанию, оставить его |
| Reply-To | Пусто |
| CC и BCC | Пусто |
| Auto-Reply / Linked Template | Выключено |

В HTML-редактор вставить содержимое
[emailjs-template.html](design/account-security/emailjs-template.html).
Сохранить шаблон и его **Template ID**.

Контракт параметров, которые передаёт сервер:

| Параметр | Содержимое |
| --- | --- |
| `to_email` | Один согласованный адрес получателя; проверяется сервером |
| `subject` | Тема служебного письма, сформированная M-Flow |
| `message` | Обычный текст письма с пояснением, логином и кодом; не HTML |
| `action_url` | Ссылка подтверждения/сброса на настроенном origin M-Flow либо пустая строка для уведомления без действия |

В шаблоне использовать **двойные** скобки `{{message}}`: EmailJS экранирует
их содержимое. Тройные `{{{message}}}` вставляют HTML без экранирования и здесь
не нужны. Текст не следует заранее преобразовывать в HTML-сущности — иначе
пользователь увидит двойное экранирование.

Блок `{{#action_url}}…{{/action_url}}` скрывает ссылку, когда действие не нужно.
Само экранирование не делает произвольный URL безопасным: сервер формирует
ссылку только из разрешённого адреса M-Flow, пути и одноразового токена.
[Переменные и условные блоки](https://www.emailjs.com/docs/user-guide/dynamic-variables-templates/).

## 4. Отключить сохранение параметров письма

В открытом шаблоне перейти на вкладку **Settings** и отключить сохранение
**Email History / истории запросов**, затем сохранить шаблон. Точное название
переключателя может отличаться: в публичной документации подтверждена вкладка,
но не приведена его текущая подпись.

Это важно для писем со ссылками восстановления. Не импортировать учеников
в списки контактов и не подключать автоответы, маркетинговые подписки или
дополнительные шаблоны рассылки. Автоответ расходует ещё один запрос.

Отключение истории параметров не означает отсутствия обработки письма или
служебных метаданных у EmailJS/Gmail. Условия хранения и использования сервиса
должны учитываться в фактических правилах обработки данных M-Flow.
[Описание истории запросов](https://www.emailjs.com/legal/privacy-policy/),
[автоответы](https://www.emailjs.com/docs/user-guide/auto-reply/).

## 5. Задать закрытую конфигурацию приложения

Для этого транспорта используются переменные процесса:

```text
M_FLOW_MAIL_PROVIDER=emailjs
M_FLOW_MAIL_FROM=АДРЕС_ПОДКЛЮЧЁННОГО_ЯЩИКА
M_FLOW_PUBLIC_URL=HTTPS_ORIGIN_СОГЛАСОВАННОЙ_ТЕСТОВОЙ_СРЕДЫ
M_FLOW_MAIL_API_KEY=PRIVATE_KEY
M_FLOW_MAIL_PUBLIC_KEY=PUBLIC_KEY
M_FLOW_MAIL_SERVICE_ID=SERVICE_ID
M_FLOW_MAIL_TEMPLATE_ID=TEMPLATE_ID
```

Значения выше — обозначения, а не готовые настройки. API Key здесь означает
**Private Key EmailJS**, а не ключ Brevo или SMTP-пароль.

Ключи не отправлять в чат, не вставлять в аргументы команд, GitHub или
браузерный код. Использовать закрытые переменные согласованной среды.
`.env.example` служит справочником: приложение не загружает `.env` автоматически.
Рабочие настройки Render/Neon по этой инструкции автоматически не меняются.

## 6. Проверить настоящую доставку

Отдельный локальный запуск с настоящей почтой ещё подготавливается.
Существующий тестовый просмотр с перехватом писем не подтверждает реальную
доставку. До проверки отправки должны быть согласованы сервис, отправитель
и конкретный тестовый получатель.

На отдельной базе с вымышленными аккаунтами обеих ролей проверить:

1. Подтверждение почты и её привязку только после POST-действия.
2. Запрос восстановления, получение письма во «Входящих» или «Спаме»,
   читаемость текста и сохранность полной ссылки с `#token=…`.
3. Смену пароля, вход с новым паролем и отзыв прежних сеансов.
4. Отказ при повторной ссылке и просрочке; просрочку проверять в тестовой среде.
5. Смену почты с отдельными подтверждениями обоих ящиков.
6. Сохранность ролей, проектов, истории и оценок.

В этой проверке настоящие письма отправляются только согласованному получателю.
Не создавать тестовые аккаунты и проекты на рабочем сайте. Не нажимать
встроенный Test EmailJS с чужим адресом для случайной проверки.

HTTP **200 / OK** означает успешную обработку API-запроса EmailJS, а не
подтверждённое получение письма. Проверить нужно сам ящик и переход по ссылке.

## Лимиты выбранного варианта

На дату подготовки руководства Free предусматривает **200 запросов в месяц**
и два шаблона. Endpoint отправки ограничен **одним запросом в секунду**.
Лимит нужно учитывать для всего отправляющего аккаунта, в том числе между
письмами смены адреса и разными процессами приложения. Частые ошибки нельзя
исправлять бесконтрольной повторной отправкой.

Для согласованной нагрузки школы требуется отдельная оценка объёма,
доставляемости, квот EmailJS и почтового ящика. Наличие тарифа Free не заменяет
эту проверку.
[Актуальные тарифы](https://www.emailjs.com/pricing/),
[REST API отправки](https://www.emailjs.com/docs/rest-api/send/).
